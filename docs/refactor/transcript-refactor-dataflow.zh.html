数据下行 · 事件上行 —— 全景

Runloop tick 契约 —— 三条关键路径

全部 UI 落点都排进顶层 CLAUDE.md 的 tick 图：source phase 里把数据、行高、几何全部备齐，beforeWaiting 只剩 CoreAnimation commit —— 首帧完整、零空白闪现。

① 首屏 attach（viewDidLayout 首次 · 全同步）

SOURCE PHASE（MainActor）
layoutSubtreeIfNeeded 稳定宽度→ loop：loadPage（同步）→ Builder.makeItems→ store.prependOlderItems→ VM sink deriveOutline（同 tick）→ 前置 top-level 高度 → cacheRowHeight …直到 viewport 满 / 文件顶（无 maxPages、无 deadline）
attach dataSource→ reloadData + restoreFolds（父先子后）→ layoutSubtreeIfNeeded（显式 tile，全 warm 命中）→ scrollRowToVisible / 恢复 anchor→ kick loadOlderPages + backfillDescendantRowHeights
BEFOREWAITING
CATransaction commit → render server⇒首帧完整，零空白

二次 mount（didLoadFirstScreen == true）：跳过 sync loop，同宽度行高缓存全 warm，直接 attach + 按 lastKnownScrollAnchor 恢复滚动位。

② 旧页 loader（每页一轮 · 三段式）

SOURCE PHASE（MainActor）
for try await page resume→ Phase 1：deriveOutline preview（同一纯函数，local 空 pool 不污染真池）
TASK.DETACHED（background）
Phase 2：算新增子树全量（top-level + 全部后代）高度
SOURCE PHASE（MainActor · withoutImplicitAnimations 包住）
checkCancellation→ captureScrollAnchor（记 node 引用 + 偏移）→ 先 warm cacheRowHeight→ prependOlderItems ⇒ 两跳 sink ⇒ applyOutline 快路径 insertItems→ restoreScrollAnchor（node 身份找回行号，视觉零跳动）

Combine 两跳都在同一 source phase：@Published willSet 同步 send；sink 只用 sink 参数、不重读属性（stash 契约）。取消三关卡：await 抛 / Phase 1 前 / Phase 2 后。

③ Fold —— native disclosure，无回环

用户点 native disclosure→ NSOutlineView 内部 expand + 动画→ didExpand / didCollapse 通知→ Controller：store.setFold→ $folds sink → applyFolds 幂等 diff→ view 已在目标态 → no-op ✓ 无回环

fold 不重派生 outline（不变式：folds 不影响树结构）；主动 fold 不锁滚动。兜底：backfill 未完成时 expand → outlineViewItemWillExpand 同步补算该 group children 高度（bounded、user-initiated，与 live-resize 同一例外类）。

生命周期三域 —— 状态住在"所有读者共享的最低作用域"

跨 mount 要活的（items / folds / 行高 / 分页位 / 滚动位）住 Session 域 Store；只在一次 mount 内有意义的（outline 派生、node 池、loader、hover）住 VC 域，prepareForRemoval 确定性拆除。

审查记录 —— 本次对照 CLAUDE.md 后直接修入方案的问题

以下修改已写回 docs/refactor/transcript-refactor.zh.md：

  1. 正确性旧页 loader 的 id 碰撞 bug（§ 6.3）：整条 stream 所有页共用 startCursor 喂 pageCursor，nil-uuid 消息的 fallback id page@cursor/msgN 会跨页碰撞 → 改为 pageCursor 逐页推进。
  2. 正确性行高缓存的 expand 漏洞（§ 4.1 / § 4.2 / § 4.4 / § 2.10）：首屏与 loader 原本只预算 top-level 高度，collapsed group 的 children 在用户 expand 时才成为 row，会在 main 懒算 miss，违反方案自己的"attach 后不许 miss"不变式 → loader Phase 2 改算新增子树全量 + 新增 attach 后 backfillDescendantRowHeights() off-main 预热 + outlineViewItemWillExpand 同步补算兜底（并补 § 11 测试）。
  3. 一致性Delegate 方法名漂移（§ 13）：requestUserBubbleSheet / requestImagePreview(image:) 是旧名，且传 NSImage 违反 § 2.9 自己的论证 → 统一为 requestUserMessageInspectSheet(itemID:) / requestImagePreview(itemID:)。
  4. 一致性§ 9.3 的 prepareForRemoval 片段漏了滚动位写回（与 § 2.10 同一方法的两个版本不一致）→ 同步补齐，并加 backfillTask cancel。
  5. 命名.toolBody 是不存在的 enum case（4 处）：orphan result 实际以 .userToolResult item 呈现、由 ToolBodyRowView 渲染 → 全部改正。
  6. 事实性§ 2.2 谎称 Builder 后缀在顶层 CLAUDE.md"明列"（实际未列）→ 改为按"避开含糊 Manager、选精确角色词"论证，仅无状态可用。
  7. 陈旧§ 10 表格两行陈旧重复（引用已废弃的 Block.id / nodeCache）→ 删除。
  8. DISDK 静态直调缺测试 seam（§ 2.10 / § 4.1 / § 6.3）：Controller 原直接调 SessionHistory 的 enum 静态方法 —— 依赖藏进方法体、无法注入 stub（与 CLAUDE.md 禁止的 .shared 同罪），§ 11 自己的 stub 测试无法落地 → 新增 SessionHistoryLoading 协议 + SessionHistoryLoader 生产实现（§ 2.13），composition root 进 AppContext、经 init 注入 Controller。

审查结论：除上述八点外，方案与顶层 CLAUDE.md 的分层 / 数据流 / DI / 列表 / 内存并发规范一致。两处看似"越界"实为合规：Controller 驱动分页（Controller 调 Service/Store 是 events-up 规定动作，I/O 实现在 Service 侧、经协议注入）；$folds 绕过 VM（VM 是可选的按面插入层，fold 面无派生职责，加 pass-through 才是违例的空转）。两处对规范字面的偏离是论证过的：不加 .receive(on:)（全链 @MainActor 同 actor 同步 send，插调度反而把同 tick 首帧契约撕成 next-tick）；首屏 main 同步 loadPage（bounded by viewport 的产品取舍，为零空白首帧）。
